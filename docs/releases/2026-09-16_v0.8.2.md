## Resumo executivo

A v0.8.2 reúne duas correções pequenas e compatíveis acumuladas após a v0.8.1:

1. **Precheck de downgrade operável em bancos com histórico v2.** O comando
   `check_specialized_procedure_downgrade` agora separa corretamente os três
   marcadores que cruzam a fronteira real do writer 3.0 dos dois marcadores
   históricos v2. `status` e exit code continuam fail-closed para writes 3.0,
   enquanto dado legado é reportado sem tornar o gate pré-cutover
   insatisfazível. O campo `old_image_return_available` explicita se a exceção
   de retorno à imagem anterior permanece disponível.
2. **Radio buttons visíveis no modo claro.** Todos os radios no shell
   hospitalar recebem borda de 2 px com o novo token
   `--hospital-control-border: #78909c`, alcançando **3,35:1** sobre branco
   (mínimo WCAG não textual: 3:1). O seletor é restrito a radios; checkboxes,
   cards, markup e estados selecionados permanecem inalterados.

Não há migration, dependência nova, alteração de FSM, payload clínico ou
contrato LLM.

## Rollback

A aplicação pode voltar para a imagem `v0.8.1` sem reverse migration porque
esta release não altera schema nem dados. A fronteira geral da ADR-0006 continua
válida: se já houver writes 3.0, não se deve retornar a uma imagem anterior ao
writer 3.0. Em caso de regressão exclusivamente visual, fix-forward de CSS é
preferível; em caso de problema no relatório do precheck, não prossiga com o
cutover até revisar manualmente as três classes bloqueantes.
