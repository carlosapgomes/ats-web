## Resumo executivo

Segundo hotfix da sequência aberta por `v0.3.0-rc.1`. Com o vínculo strict V2
correto (rc.2), o schema real do LLM1 passou a ser enviado à API, que o
rejeitou com `400 invalid_json_schema`: a união discriminada de
`requested_procedures` serializa como `oneOf` + `discriminator`, construções
não suportadas pelo modo strict (uniões apenas via `anyOf`). A correção
reescreve `oneOf`→`anyOf` e remove `discriminator` **somente na cópia do
schema enviada à API**; modelos Pydantic e validação local permanecem
inalterados (o discriminador continua ativo em
`Llm1ResponseV2.model_validate`).

## Incidente corrigido

- Caso `9f1e9d3a-0d5e-4dd6-ac00-cd4b178a4ec4`, produção 2026-08-09:
  `openai.BadRequestError 400 invalid_json_schema — In context=('properties',
  'requested_procedures', 'items'), 'oneOf' is not permitted.`
- Verificação empírica pós-correção: schema normalizado do LLM1 com
  `oneOf: 0`, `discriminator: 0`, `anyOf: 40`; união preservada com as duas
  variantes `$ref` (`Llm1EdaProcedureV2`, `Llm1ColonoscopyProcedureV2`).
- Casos afetados: tratados operacionalmente por encerramento administrativo +
  reapresentação.

## Specs atualizadas

- [`procedure-neutral-analysis`](../../openspec/specs/procedure-neutral-analysis/spec.md)
  — novo requisito: schema enviado à API converte uniões `oneOf` para `anyOf`
  e remove `discriminator`, preservando modelos e validação local.
