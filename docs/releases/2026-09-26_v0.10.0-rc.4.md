# Release Evidence Pack — v0.10.0-rc.4

**Data:** 2026-09-26 · **Tipo:** prerelease (hotfix de apresentação sobre `v0.10.0-rc.3`)
**Versão anterior:** `v0.10.0-rc.3` · **Tag/commit:** `v0.10.0-rc.4` / merge `77b6d2b`

## Resumo

No smoke do rc.3, o dono observou texto de comentário renderizado no card de
correção: o comentário `{# ... #}` deixado pelo slice do rc.3 ocupava **três
linhas** e, no Django, esse sintaxe só é comentário em linha única — o lexer
não o reconheceu e o texto vazou para o HTML. Correção QUICK: conversão para
bloco `{% comment %}` (multi-linha seguro) + guarda de regressão no teste de
view (nenhum `{#` alcança o card renderizado). Verificado que os demais
comentários `{#` do projeto são todos de linha única (válidos).

## Validação

- `apps/intake/tests/test_exam_type_correction.py`: 69 passed (inclui a
  guarda nova); ruff/format limpos no arquivo tocado.
- Sem mudança de comportamento além do HTML (template + teste apenas).

## Operação

Sem migration, sem prompts, sem dados. Deploy padrão; rollback = imagem rc.3.
Smoke: o card deve exibir apenas Tipo declarado / Tipo detectado / Motivo da
revisão (com origem), sem nenhum texto de comentário.
